# Contributing to IRENX Gateway

Thank you for contributing.

## Before opening a PR

1. Keep secrets out of source code, tests, logs, and documentation.
2. Run the local typecheck and deployment dry run.
3. Keep provider-specific changes isolated where possible.
4. Add or update tests for behavior changes.
5. Explain security implications for gateway/auth/routing changes.

## Pull requests

Use a focused branch and describe:

- what changed;
- why it changed;
- how it was tested;
- whether Cloudflare configuration is required;
- whether API compatibility changed.

## Security-sensitive changes

Do not disclose credentials or exploit details in public issues. Follow `SECURITY.md` for private vulnerability reporting.
